## What must be taught

| ID | Status | Requirement |
|---|---|---|
| 00.02.01 | 🟥 | Activity A: research notes (facts & figures only - no analysis) that may be taken into supervised sessions |
| 00.02.02 | 🟥 | Proposal contents: business context, functional & non-functional requirements, decomposition, KPIs, user acceptance criteria, risk mitigation, legal/regulatory compliance, justification |
| 00.02.03 | 🟥 | Design documents: interface designs, data requirements (ERD, data dictionary), algorithm designs (up to ~5 key problems), test strategy |
| 00.02.04 | 🟥 | Activity C: using generative AI for snippets - prompt log, evaluation of output, refinement |
| 00.02.05 | 🟥 | Designs detailed enough for a third-party developer AND understandable by non-technical stakeholders |
| 00.02.06 | 🟥 | Solution must be complex enough to need at least two languages (front end + back end) |
