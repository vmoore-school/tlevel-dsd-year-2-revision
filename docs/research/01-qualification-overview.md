# 01 Qualification Overview

**Qualification:** T Level Technical Qualification in Digital Software Development (Level 3)
**Awarding organisation:** Pearson · **Qualification number:** 610/5801/4
**First teaching:** September 2025 · **Specification used for this guide:** Version 1.1, August 2026

> "DSD" replaced the older *Digital Production, Design and Development* (DPDD) T Level. Most DPDD
> resources are still useful, but the DSD specification is the one that counts. Where this guide
> relies on DPDD material it says so.

## The whole T Level

| Part | What it is | When (typical) | Grade |
|---|---|---|---|
| Core component | Core Paper 1 + Core Paper 2 + Employer Set Project (ESP) | **Year 1** (summer series) | A* to E |
| Occupational Specialism (OS) | One synoptic project: Digital Software Development | **Year 2** (March to May window) | Distinction / Merit / Pass |
| Industry placement | At least 315 hours (about 45 days) with an employer | Across both years, mostly Year 2 | Must be completed (not graded) |

To get the T Level you need **at least an E in the Core, at least a Pass in the OS, and a completed
industry placement**. The overall grade (Distinction*, Distinction, Merit, Pass) comes from the DfE
look-up table that combines the Core and OS grades.

## Core component (Year 1, assumed known)

| Assessment | Duration | Marks | Weighting in Core | Series |
|---|---|---|---|---|
| Core Paper 1 (problem solving, programming, emerging issues, legislation) | 2h 15m | 90 | 30% | June / November |
| Core Paper 2 (business context, data, digital environments, security) | 2h 15m | 90 | 30% | June / November |
| Employer Set Project (plan, debug, design, develop in Python with pandas and matplotlib, evaluate) | 14h 30m | 100 | 40% | May / November |

Core UMS: the two exams together give 240 UMS, the ESP gives 160 UMS, 400 in total.
A* 360+, A 320+, B 280+, C 240+, D 200+, E 160+.

Core resits are possible in a later series. This guide does not re-teach the Core, but
[03-year1-vs-year2-map.md](03-year1-vs-year2-map.md) shows exactly which Core topics the OS builds on.

## Occupational Specialism (Year 2, what this guide covers)

| Item | Detail |
|---|---|
| Method | Externally set, externally marked (by Pearson) synoptic project |
| Duration | 50 hours 30 minutes of supervised time, over several sessions |
| Marks | 144 raw marks, graded directly (no UMS) |
| Window | One window a year, **March to May** |
| Weighting | 100% of the OS = 50% of the T Level |
| Languages | At least two of: Python 3 (3.10+), C#, SQL, JavaScript, PHP |

### Performance Outcomes (POs)

| PO | Description | Marks | % |
|---|---|---|---|
| PO1 | Analyse a problem to define requirements and acceptance criteria, aligned to user needs | 24 | 16.7% |
| PO2 | Design, implement and test software | 57 | 39.6% |
| PO3 | Change, maintain and support software | 18 | 12.5% |
| PO4 | Create solutions in a social and collaborative environment | 9 | 6.3% |
| PO5 | Discover, evaluate and apply reliable sources of knowledge | 18 | 12.5% |
| PO6 | Apply ethical principles and manage risks in line with legal and regulatory requirements | 18 | 12.5% |

### OS content areas (the "what to know" list)

1. Analyse a problem to define requirements and acceptance criteria aligned to user needs
2. Apply ethical principles and manage risks in line with legal and regulatory requirements
3. Discover, evaluate and apply reliable sources of knowledge
4. Design
5. Create solutions in a social and collaborative environment
6. Implement a solution using at least two appropriate languages
7. Testing a software solution
8. Change, maintain and support software

Each content area is a subject folder in [`curriculum/`](../../curriculum/README.md).

> Students are **not** assessed on knowledge outcomes directly. They have to *apply* the knowledge
> through the PO skills in response to the scenario. So every lesson should finish with something
> students can do in a project, not just recall.

## Results

- Summer series results: August (Level 3 results day).
- The first live DSD OS series is **summer 2027**, for the cohort that started in September 2025, so
  there are no DSD past papers or grade boundaries yet. Expect around 30% for a Pass, 50% for a Merit
  and 70% for a Distinction, going by DPDD. This is an estimate, not an official figure.

## Resources Pearson expects centres to have (OS)

Python 3.10+ and the chosen languages, IDEs and debuggers, automated testing tools (UI, performance,
load/stress, compatibility), online code repositories (e.g. GitHub), forums, survey tools (e.g. Google
Forms), AI code-generation tools, screencasting/video editing software, microphones and headphones, a
web server, database software, backup and encryption tools.
